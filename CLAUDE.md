This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

CREAM = **Credence Real Estate & Asset Management** website. The repo currently holds **two coexisting codebases** mid-migration:

1. **Legacy static site** (repo root) — hand-coded, generated by a zero-dependency Node script from JSON data, committed as plain HTML. Still the live production site on Hostinger (behind Cloudflare, forms via Web3Forms).
2. **New dynamic app** (`cream-app/`) — a Laravel app replacing the static site: DB-driven public pages + a private staff dashboard at `/staff`. This is where **active work happens** (branch `dynamic-site`).

The rebuild is done in **numbered phases** (Plan → Foundation → Assets → Articles/comments → Testimonials/QR → Forms/enquiries → Settings/users/polish → Analytics → Testing/packaging). Finish a phase, run its checks, commit on `dynamic-site`, report, and **stop for approval** before the next. Don't roll phases together.

## Ground rules (these override default instincts)

- **Never deploy or touch the live server.** The owner deploys manually (scp / Hostinger File Manager). Make deployment simple; never run it.
- **Never invent content** (listings, prices, testimonials, staff, articles). Seed only from the existing `data/*.json` and pages. Mark gaps `TODO(sam)`.
- **Keep the public design and URLs.** Same fonts/colours/layout; every URL the static site exposed must still resolve (301s only where unavoidable).
- **No secrets in git.** `cream-app/.env` is git-ignored; `.env.example` carries placeholders.
- Forms are **Laravel-handled** (Phase 6). Every public form posts to `POST /enquiries` → one `Enquiry` model (typed `details` JSON), with CSRF + honeypot + Turnstile + rate limit; each submission queues an `EnquiryReceivedMail` to `config('cream.moderation_email')` and appears in the staff inbox at `/staff/enquiries`. Web3Forms is fully removed.

## Local toolchain — important, non-obvious

Development is on Windows with **Laravel Herd**. Two gotchas:

- Herd's default `php` is **8.5**, but this project targets **PHP 8.4** (matches Hostinger). Always use the **`php84`** shim, and prepend Herd's bin to PATH first:
  ```bash
  export PATH="$HOME/.config/herd/bin:$PATH"   # bash
  # PowerShell: $env:Path = "$env:USERPROFILE\.config\herd\bin;" + $env:Path
  ```
  Run Composer under 8.4 too: `php84 "$HOME/.config/herd/bin/composer.phar" <args>` (platform is pinned to 8.4 in `composer.json`).
- The database is a **portable MariaDB 10.11** that does **not auto-start** and stops when the session ends. Start it manually before migrating/serving:
  ```
  C:\Users\qsamm\mariadb\mariadb-10.11.19-winx64\bin\mysqld.exe --no-defaults --datadir=C:\Users\qsamm\mariadb-data --port=3309 --bind-address=127.0.0.1 --console
  ```
  The port must match `DB_PORT` in `.env` (currently **3309**). Databases `cream` (dev) and `cream_test` exist; user `cream` / password in `.env`.

## Commands

### Static site (repo root)
```bash
node scripts/build.mjs        # regenerate all HTML from data/*.json + scripts/pages/*
node scripts/check-links.mjs  # no broken internal links / stray href="#" / Drive-Unsplash links
node scripts/check-shared.mjs # header & footer identical across generated pages
```

### Laravel app (run inside cream-app/, with php84 on PATH)
```bash
php84 artisan migrate                 # needs MariaDB running
php84 artisan cream:import-static      # seed assets from ../data/listings.json (+ photos); idempotent
php84 artisan cream:create-admin       # interactive: creates the first admin (no hard-coded creds)
php84 artisan serve --host=127.0.0.1 --port=8000
php84 artisan test                     # full suite (runs on in-memory SQLite — no MariaDB needed)
php84 artisan test --filter=AssetCrudTest                 # one test class
php84 artisan test tests/Feature/Auth/LoginTest.php       # one test file
php84 "$HOME/.config/herd/bin/composer.phar" audit        # dependency vuln check (run each phase)
```

Tests run on **in-memory SQLite** (see `phpunit.xml`); migrations are written portably so they also apply on MariaDB (verified by the real `migrate`). Turnstile and the breached-password HIBP check are disabled in the test env.

## Architecture — the big picture

### Static site (legacy)
`node scripts/build.mjs` reads `data/{listings,site,posts,popup}.json` and emits committed HTML. Shared header/footer/drawer/popup come from **one** place (`scripts/components.mjs`); page bodies from `scripts/pages/*.mjs`. Edit JSON + rebuild, never hand-edit generated HTML. This is the source of truth the Laravel import seeds from.

### Laravel app (`cream-app/`)
- **Auth** = Laravel **Fortify**, all under the `/staff` prefix (login, TOTP 2FA + recovery codes, password reset). No public signup. Roles are an `admin`/`staff` enum on `users`; 2FA is mandatory for admins (enforced by `RequireTwoFactorForAdmins` middleware). Key wiring: `app/Providers/FortifyServiceProvider.php` (views, Turnstile-gated `authenticateUsing`, per-email+per-IP rate limits, login/logout/failed-login activity logging), `config/fortify.php` (prefix `staff`, home `/staff`), `bootstrap/app.php` (middleware aliases: `admin`, `active`, `2fa.admin`; global `RedirectLegacyHtml`; appended `SecurityHeaders`).
- **Public site** is Blade, DB-driven, same design: `resources/views/public/*` + components in `resources/views/components/*` (icon, listing-card, money, placeholder, page-hero, filterbar). The master layout is `public/layout.blade.php`; `PublicController` serves every page. Site config (phone, socials, office details, Web3Forms keys) lives in **`config/cream.php`** (ported from `data/site.json` so the app is self-contained in production — the static `data/` folder is NOT deployed with it). Canonicals/OG use `APP_URL`, never a hard-coded domain.
- **Assets** (properties/land/projects/short-stays) are the `Asset` model with `AssetCategory`/`AssetStatus`/`Currency` enums, `asset_media`, and `asset_redirects`. Slug + reference auto-generate; **changing a slug writes a 301 redirect**. Only `published`/`under_offer`/`sold`/`let` are public; sold/let are hidden from default grids. Dashboard CRUD: `app/Http/Controllers/Staff/Asset*Controller.php` + `AssetPolicy` (staff manage; admin-only restore/permanent-delete); routes in `routes/staff-assets.php`.
- **Media**: `app/Support/ImageProcessor.php` (Intervention Image v4) re-encodes uploads to **WebP at 1600 + 800px**, strips EXIF, validates real image content, random names. Served from a `uploads` disk = `public/uploads` (→ `public_html/uploads` in prod, **no `storage:link` symlink**; configured in `config/filesystems.php`).
- **Security**: `SecurityHeaders` middleware sets HSTS/nosniff/frame/referrer/permissions headers + a **CSP that differs for public vs `/staff`** (`/staff` is also `noindex`). The public site has **no inline scripts** (hero/reels/popup run from `public/assets/site.js`) so `script-src` stays `'self'`. Every create/update/delete/login is written to `activity_log` via `App\Support\ActivityLogger` (IPs stored only hashed).
- **Server layout (prod)**: app lives outside `public_html`; only the contents of `public/` sit inside it (Hostinger's doc root can't move). `.env`/`vendor`/`storage` are not web-reachable by construction.

### Where the static→dynamic seam is
`cream:import-static` reads `../data/listings.json` and `../assets/*` from the repo root (the static site) to seed the DB. The static site and its `data/` are the import source and the rollback reference until cut-over (final phase).
